# 露光・保存

露光に関する設定、2次元検出器のROIに関する設定、およびbackgroundの差し引きに関する設定は、それぞれ **Measurement**・**ROI Settings**・**Background** から行います。


<img src={require('@site/static/img/usage_acquisition.jpg').default} style={{maxWidth: '480px'}} />



## 露光時間

**Detector Configurations** サブパネルにある以下のコントロールで、検出器の基本的な取得条件を設定します。

- **Acquisition time (s)**: 露光時間。
  値を入力してフォーカスを外す（あるいはEnter）と、その場でカメラに適用されます。
  適用中はスピンボックスが一時的に無効化され、カメラが実際に受け付けた値（SDKの都合で丸められる場合があります）が返ってくると再度有効になり、その値で表示が更新されます。
- **EM Gain (×)**: 電子増倍（EM）ゲインに対応した機種（Princeton Instrumentsの一部のカメラなど）でのみ表示される項目です。
  対応していない機種では行ごと非表示になります。
  設定可能な範囲・刻み幅はカメラ自身が報告する値がそのまま使われ、Acquisition timeと同様に値を確定するとカメラへ適用されます。
- **Cooler target temp (°C)** / **Read current temperature**: 検出器の冷却制御に対応した機種でのみ表示されます。
  目標温度を設定・確定するとカメラへ適用され、以後は5秒おきに自動で現在温度が読み出されてラベルに反映されます（`-65.0 °C Stabilised` のように、安定・ドリフト・冷却異常・冷却オフといった状態が文字列として付記されます）。
  安定（Stabilised／Locked）と判定されると自動読み出しは停止し、新しい目標温度を設定するか再接続するまで再開しません。
  手動の **Read current temperature** はいつでも押せますが、自動読み出しを再開させることはありません。

## 積算回数

- **Accumulations**: 1回の測定として扱う生フレームの積算数（1〜99999）。
  指定した数だけ検出器からフレームを取得して合算し終えると、その結果が1つのスペクトル／イメージとしてプロット・フィット・保存の対象になります。
  積算数が2以上のときは、プロット上部に `Acquired: N / M` という進捗ラベルが表示されます。
- **Cosmic ray removal**: 1Dスペクトルの積算時のみ有効な機能で、積算数が5〜2000回の範囲にあるときだけ実際に働きます（範囲外の場合は通常通り単純合算されます）。
  各ピクセルについて積算対象フレーム全体の中央値と比較し、**Spike threshold** で指定した倍率（ノイズの標準偏差の何倍か）を超えて突出した値だけを中央値に置き換えてから合算します。
  宇宙線由来のスパイクは通常のノイズよりずっと大きいため、ある程度高い閾値（既定10.0）でも取りこぼしにくく、逆に閾値を下げすぎると通常のノイズも誤って除去対象になります。
  2Dイメージ表示では効果がありません。

## ROI

**ROI Settings** パネルで、検出器のどの範囲をどう読み出すかを選びます。

- **2D Image View**: 検出器の生の2Dイメージをそのまま表示します（垂直方向のビニングなし）。
- **1D Spectrum (Full Range Binning)**: 検出器の全行を1本のスペクトルに合算します。
- **1D Spectrum (Custom ROI)**: 下の **Start Row** / **End Row** で指定した行の範囲だけを合算します。
  迷光や不要な行を除いて、シグナルのある範囲だけを使いたいときに使います。

Start Row / End Rowはこのモードを選んでいるときだけ編集可能です。
ROIの値を変更すると、現在選択中の回折格子に対する既定値として `spectrometerConfig.json` に自動保存され、次回そのグレーティングでアプリを起動したときに読み込まれます（アプリ実行中にグレーティングを切り替えても、ROI欄の値はそのままです。
グレーティングごとの既定値が使われるのはアプリ起動時だけです）。

**2D Image View** を選ぶと、Backgroundパネルの **Subtract background** は自動的にOFFになり、ON側の選択自体が無効化されます（背景差し引きは1Dスペクトルに対してのみ意味を持つためです）。

**Flip X-axis** チェックボックスは、横軸（波長・Raman shift・pixelいずれの場合も）を反転して表示・保存します。
ROIの行選択（縦方向）とは独立で、回折格子ごとではなく設定全体で1つの値として保存されます。

## 連続露光

- **Take single spectrum**: 積算1サイクル分（Accumulationsで指定した枚数）を取得すると自動的に停止する単発測定です。
- **Commence Measurement** / **Terminate Measurement**: 積算サイクルを繰り返し実行し続ける連続測定です。
  1サイクル終えるたびにプロットが更新され、**Terminate Measurement** を押すまで（あるいはハードウェアエラーで自動停止するまで）継続します。

**Take single spectrum**・**Commence Measurement**・**Start Sequential**・**Acquire and save background**、および[Calibrate x-axis](grating-calibration.md#横軸較正)は、同時に1つしか実行できません。
いずれかの実行中に別の操作を試みると "Busy" の警告が表示され、その操作は行われません。

また、**Subtract background** がONで、かつ読み込み済みのバックグラウンドが現在の露光時間・積算回数・ROIなどと食い違っている場合、これらの操作を開始する直前に警告ダイアログが表示されます。
「Ignore and continue」で不一致を無視して続行するか、「Quit」で操作を取りやめるかを選べます（詳細は下記「[バックグラウンドの取得と差し引き](#バックグラウンドの取得と差し引き)」を参照）。

### Sequential measurements（連続測定）

**▶ Sequential measurements** を開くと、一定間隔でスペクトルを自動保存し続ける連続測定の設定が現れます。

1. **Choose directory** で保存先フォルダを選びます（前回選んだフォルダは次回起動時も記憶されています）。
   フォルダを選ぶまで **Start Sequential** は押せません。
2. **Skip frames** で、保存する頻度を指定します。
   Nに設定すると「1フレーム保存 → 続くN回は保存せず破棄」を繰り返します。
   例えば露光時間0.1 s・Skip frames=9なら、10フレームごと（1.0 s間隔）に1枚保存されます（詳細はUI上の「how this works?」リンクからも確認できます）。
3. **Max. number** で、保存する最大フレーム数を指定します。
   到達すると自動的に停止します。
4. **Start Sequential** を押すと、連続測定がまだ動いていなければ自動的に開始され、以後は積算サイクルが完了するたびにSkip framesの設定に従って保存するかどうかを判定します。
   保存されたフレームは[スペクトルデータファイル](../data-formats/spectrum-data.md)と同じ形式で、通し番号とタイムスタンプを含むファイル名（`seq_00000_...txt`）で書き出されます。
   フィッティングがONの場合は、保存のたびに実行全体のサマリファイルにも1行追記されます。

実行中は測定条件・回折格子・較正・フィッティングなど、表示スタイル（Line/Scatter、自動リスケール）を除くほぼすべてのコントロールがロックされます。
**Terminate Measurement** も無効化されるため、停止するには**Stop Sequential** を押します。
停止すると、開始・終了時刻や露光時間・積算数・Skip frames、保存されたフレームの一覧を記録したサマリファイルが選択フォルダ直下に書き出されます（形式は[連続測定ログファイル](../data-formats/sequential-log.md)を参照）。

## バックグラウンドの取得と差し引き

**Background** パネルでは、暗電流や迷光を差し引くためのバックグラウンドスペクトルを扱います。

- **Acquire and save background**: 現在のAcquisition time・Accumulations・ROIでバックグラウンドを1回取得し、保存ダイアログでファイルへ書き出します。
  保存が成功すると、そのままアプリ内にも読み込まれた状態になり、**Subtract background** が自動的にONになります。
- **Load background**: 以前保存したバックグラウンドファイルを直接読み込みます。
- **Subtract background (ON/OFF)**: 差し引きを行うかどうかの切り替えです。
  2D Image View表示では選択できません（上記「ROI」参照）。

差し引きは、読み込み済みバックグラウンドのデータ長が現在のデータ長（＝ROIの行数）と一致している場合にのみ実際に適用されます。
長さが一致しない場合は、バックグラウンドは読み込まれたままですが差し引きは行われず、生カウントがそのまま表示・保存されます。
露光時間・積算回数・ROI・（分かる場合は）機種情報や冷却温度設定なども継続的に比較されており、これらが食い違った状態で測定を開始しようとすると、前述の不一致警告ダイアログが表示されます。
ファイル形式の詳細は[バックグラウンドファイル](../data-formats/background.md)を参照してください。

## データの保存

- **Save data**: 現在表示中の1Dスペクトルまたは2Dイメージを、保存ダイアログ（既定では前回保存したフォルダとタイムスタンプ付きファイル名）から書き出します。
  ファイル形式は[スペクトルデータファイル](../data-formats/spectrum-data.md)を参照してください。
- **Save fitting results**: フィッティングがONのときだけ有効になるチェックボックスです。
  ONにして**Save data** を実行すると、スペクトル本体と同時に同じフォルダへ[フィッティング結果ファイル](../data-formats/fitting-results.md#単発測定-_fitting_resultstxt)（`<ファイル名>_fitting_results.txt`）も書き出されます。

Sequential measurement実行中は、この**Save data**ボタン自体が無効化され、前述の通りSkip framesの設定に従って自動的に保存が行われます。
