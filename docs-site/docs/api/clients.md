# クライアントと認証

すべてのエンドポイントは `X-API-Key` ヘッダーを必要とします。

```
X-API-Key: <クライアントに割り当てたキー>
```

キーは**クライアント（連携アプリケーション）ごとに1つ**発行します。
メニューバーの **API → Manage Clients...** で一覧・追加・失効ができます。

## なぜクライアントごとに分けるのか

単一キーでは「この要求元は秘密を知っている」ことしか確認できず、
「許可したN個のアプリケーションのうちのどれか」を区別できません。
常時待ち受け（[Standby](standby.md)）ではこの区別が実務上重要になります。
研究室で実際に起きるのは悪意ある攻撃よりも**事故**で、
同じキーを複数台の設定にコピーした結果、A号機のスクリプトがB号機を叩く、
止め忘れた古いクライアントが動き続ける、といったケースが典型です。

クライアントを分けておけば、**片方だけを失効させる**ことができ、
「どのクライアントが最後にいつ測定を叩いたか」もパネルとダイアログに残ります。

## Manage Clients ダイアログ

| 列 | 内容 |
|---|---|
| Name | クライアント名（実験記録として意味のある名前を推奨） |
| Key | キー（既定はマスク表示。**Reveal key** で表示、**Copy key** でコピー） |
| Allowed IPs | 許可する要求元アドレス。空欄なら**どのアドレスからでも許可** |
| Created | 作成日時 |
| Last request | 最後にリクエストが届いた時刻と要求元アドレス |

- **Add…**: 新しいクライアントを追加し、キーを自動生成します。
- **Rename… / Allowed IPs…**: 名前・許可IPを編集します。
- **Regenerate key**: そのクライアントのキーだけを再発行します。他のクライアントには影響しません。
- **Revoke**: そのクライアントを削除します。

編集内容は **Save** を押した時点で反映されます。サーバーの再起動は不要で、
**次のリクエストから**新しい設定が使われます。

:::caution
全クライアントを削除すると、すべてのリクエストが `401` になります。
この状態はアプリを再起動しても維持されます（「意図的に全部失効させた」状態として扱うため、
キーの自動生成は行いません）。
:::

## 許可IP

`Allowed IPs` には単一アドレスとCIDR記法を書けます（カンマ区切り）。

```
192.168.1.42
192.168.1.42, 192.168.2.0/24
```

- 空欄は「制限なし」です。
- 許可外のアドレスから正しいキーで来たリクエストは `403 Forbidden` を返します
  （`code: "ip_not_allowed"`、detail にクライアント名と要求元アドレスを含みます）。
  キーそのものが未知の場合は `401` です。この2つを区別するのは、
  設定ミスの切り分けを優先しているためです。
- IPv4射影アドレス（`::ffff:192.168.1.42`）は自動的に正規化されるため、
  `192.168.1.42` と書けば一致します。

:::note
DHCPで要求元のアドレスが変動する環境では単一アドレス指定は破綻します。
その場合はCIDRでサブネットを指定するか、許可IPを空欄のままにしてください。
:::

## キーの保存場所と旧バージョンからの移行

キーはアプリケーションデータディレクトリの `FluoraPressee/api_clients.json` に保存されます。

| OS | パス |
|---|---|
| Windows | `%LOCALAPPDATA%\FluoraPressee\api_clients.json` |
| macOS | `~/Library/Application Support/FluoraPressee/api_clients.json` |
| Linux | `$XDG_DATA_HOME/FluoraPressee/api_clients.json`（既定 `~/.local/share/...`） |

ファイルは一時ファイル経由で原子的に置き換えられ、POSIX系では所有者のみ読み書き可（`0600`）に
設定されます（Windowsではファイル権限がほぼ機能しないため、ユーザープロファイル配下という
保存場所自体が保護になります）。

**旧バージョンからの移行は自動です。** リポジトリ直下の `fluora_pressee_api_key.json` に
単一キーが保存されていた場合、初回起動時に `default` という名前のクライアント
（許可IPなし＝制限なし）として取り込まれ、旧ファイルは削除されます。
**キーの値はそのまま引き継がれる**ため、既存の連携アプリケーションは設定変更なしで動作を続けます。

## `/docs` の公開

FastAPI の対話的ドキュメント（`/docs`, `/redoc`, `/openapi.json`）は
APIキーの認証を通らないため、**既定では無効**（`404`）です。
必要な場合のみ「API Server」パネルの **Expose /docs** を有効にしてください。
この設定は次回サーバー起動時から反映されます。
