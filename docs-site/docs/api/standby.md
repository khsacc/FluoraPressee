# 動作モード（Off / Standby / Locked）

APIサーバーの動作は「API Server」パネルの **Mode** で選びます。

| モード | 待ち受け | GUIの測定・設定系コントロール |
|---|---|---|
| **Off**（既定） | しない | 常に操作できる |
| **Standby** | 常時 | **APIリクエストが実際に装置を操作している間だけ**ロックされる |
| **Locked** | 常時 | サーバーが起動している間ずっとロックされる |

**Locked は従来の "Start API Server" と同一の挙動です。** 既存の運用手順をそのまま続ける場合は
Locked を選んでください。

## Standby モード

リモートから測定したくなるたびに操作者が実機の前まで行ってサーバーを起動する、という手間を
なくすためのモードです。サーバーは常時待ち受けますが、GUIは普段どおり操作できます。

- リクエストが装置の操作を始めた瞬間に測定・設定系コントロールがロックされ、
  パネルに **● Remote control active** が点灯します。
- リクエストが終わってから **解除待ち時間**（既定1.0秒、パネルで0.5〜10.0秒に変更可）が経過すると
  ロックが外れます。連続してリクエストが届いている間はロックが維持されるため、
  コントロールが何度も点滅することはありません。
- ロック直前にフォーカスがあったウィジェットには、解除時にフォーカスが戻ります。

解除待ち時間はロックが解けるまでの猶予であって、リクエストの締切ではありません。
長い積算取得の途中でこの時間が経過してロックが外れることはありません
（計測はリクエストの終了時点から始まります）。

### モードの永続化と自動開始

選んだモードは保存され、次回起動時に自動的に復帰します。Standby / Locked のまま終了した場合、
次の起動では**ハードウェアの初期化が終わったあとに**自動で待ち受けを開始します。

ポートが他のプログラムに使われているなど、待ち受けの開始に失敗した場合はモードが Off に戻り、
その旨のダイアログが出ます（黙って待ち受けていない状態にはなりません）。
カメラの初期化に失敗した状態でも待ち受けは再開しますが、その状態で届いた取得リクエストは
`503`（`code: "camera_not_ready"`）を返します。

## ローカル操作との排他

同時に装置を操作できるのは1つだけ、という原則はモードによらず同じです。
ローカルの測定・分光器移動・構成ロード・背景の取得/読み込み・ハードウェア設定ダイアログ・
Instrument Status の更新はいずれも同じ排他ゲートを取るため、
その最中に届いたリクエストは `409 Conflict` を返します。詳細は `detail.reason` で判別できます。

| `reason` | 意味 |
|---|---|
| `local_sequential_run` | Sequential測定の実行中 |
| `local_operator_action` | 操作者によるローカル操作の実行中 |
| `another_api_request` | 別のAPIリクエストが装置を使用中 |

逆に、Standbyモードでリクエストが装置を操作している間は、ローカル側の測定操作や
ハードウェア設定ダイアログが拒否されます。

## Off への切り替え

**Off への切り替えは「新規リクエストの受付を停止する」という意味であり、実行中の操作を
中断するものではありません。**

- 切り替えた瞬間から、新しいリクエストは `503`（`code: "shutting_down"`）を返します。
- 実行中の取得や分光器の移動は最後まで完了します。その間パネルは "Stopping…" を表示します。
- 完了するとサーバーが停止し、ローカルの操作権が戻ります。

リクエストが進行中にモードを切り替えようとすると、その旨の確認ダイアログが出ます。
アプリケーション自体を終了する場合はプロセスごと終了するため実行中の操作が中断されうるので、
やはり確認ダイアログが出ます。

## セキュリティ上の前提

**通信はTLSで保護されていません。** APIキーは同一ネットワークセグメント上で受動的に傍受され
うる状態で流れます。自己署名証明書の配布コストに対して研究室LAN内運用での見返りが薄いと
判断したうえでの設計です。

Standbyは終日待ち受けるモードであるため、**信頼できるLAN内での運用を前提とします。**
不特定多数がアクセスできるネットワークでは使用しないでください。
待ち受けアドレスを `127.0.0.1`（このPCのみ）に制限する、クライアントごとに
[許可IP](clients.md)を設定する、といった対策も併用してください。
